# ⚠️ УСТАРЕЛ / DEPRECATED

> **Этот плагин больше не поддерживается. Причина:**
>
> С 5 августа 2026 года ModelScope внедрил кредитную систему «魔粒» (Magicube), заменив прежний фиксированный дневной лимит бесплатных вызовов. Заголовки ответов API-Inference больше не содержат информацию о квоте `modelscope-ratelimit-*-remaining`. Функция **мониторинга квот**, от которой зависит этот плагин, перестала работать.
>
> Логика интеллектуального переключения (переключение при ошибках, перерыв при 429, сжатие изображений и т.д.) возможно, будет перенесена в плагин [generic_fallback](https://github.com/sch-chun/astrbot_plugin_generic_fallback). Рекомендуется миграция.
>
> Для продолжения использования бесплатного API ModelScope рекомендуется настроить его как обычного OpenAI-совместимого провайдера.

# ModelScope Auto Proxy — Плагин AstrBot

Оборачивает бесплатные эндпоинты API-Inference от [ModelScope](https://modelscope.cn) в OpenAI-совместимый интерфейс с автоматическим переключением между моделями при сбоях.

> ModelScope предоставляет **большое количество бесплатных API-вызовов в день** для каждого аккаунта (лимиты зависят от модели). Этот плагин позволяет использовать их как единую модель — автоматически переключаясь между моделями, пропуская те, у которых исчерпана квота, и восстанавливая их на следующий день.

## Возможности

- **🧩 Плагин AstrBot** — Готов к использованию; настраивается напрямую в панели управления AstrBot.
- **🔄 Поддержка нескольких виртуальных моделей** — Одновременное предоставление нескольких виртуальных моделей, каждая со своим списком переключения и опциональным резервным провайдером.
- **🔁 Автоматическое переключение при сбое** — При ошибке (HTTP 5xx, тайм-аут, ошибка соединения и т.д.) запрос автоматически повторяется на следующей модели.
- **📊 Контроль квоты по заголовкам ответа** — Определяет остаток квоты из заголовков `modelscope-ratelimit-*-remaining`, проактивно отключая модели до получения HTTP 429.
- **🛡️ Глобальный резерв квоты** — Установите `global_quota_reserve`, чтобы остановить все вызовы при остатке квоты ≤ этого значения, защищая другие сервисы (например, генерацию изображений).
- **🔒 Аутентификация по API-ключу** — Опциональная установка API-ключа для самого прокси для предотвращения несанкционированного доступа.
- **🌐 Настраиваемый адрес прослушивания** — По умолчанию `127.0.0.1`; можно изменить на `0.0.0.0` для внешнего доступа.
- **📈 Панель мониторинга** — Встроенный WebUI для визуализации квоты пользователя и статуса каждой модели.
- **⏱ Ежедневный авто-сброс** — Все отключённые модели автоматически активируются в полночь.
- **🚦 Полная поддержка стриминга** — SSE-стриминг работает безупречно.

## Быстрый старт

### 1. Установка плагина

В панели управления AstrBot перейдите в **Рынок плагинов**, найдите `Modelscope Proxy` и установите его.

### 2. Получение API-ключа ModelScope

Перейдите на [страницу токенов ModelScope](https://modelscope.cn/my/myaccesstoken) и создайте Access Token.

> **Примечание:** После регистрации необходимо привязать аккаунт Alibaba Cloud и пройти верификацию личности перед использованием API-Inference.

### 3. Настройка плагина

Заполните конфигурацию в панели управления AstrBot в разделе **Настройки плагина** (v0.3.0+ использует новый формат с несколькими виртуальными моделями):

| Параметр | Тип | По умолчанию | Описание |
|----------|------|--------------|----------|
| `modelscope_api_key` | string | `""` | Ваш Access Token ModelScope (обязательно) |
| `proxy_port` | int | `3473` | Порт прослушивания прокси-сервера |
| `proxy_host` | string | `"127.0.0.1"` | Адрес прослушивания (оставьте localhost или установите `0.0.0.0` для внешнего доступа) |
| `proxy_api_key` | string | `""` | API-ключ прокси (опционально; при установке клиенты должны передавать `Authorization: Bearer <key>`) |
| `log_response` | bool | `false` | Включить для логирования тела ответа upstream в режиме отладки |
| `global_quota_reserve` | int | `0` | Глобальный резерв квоты (вызовы); останавливает все запросы к ModelScope при остатке ≤ этого значения |
| `virtual_models` | template_list | `[]` | **Список конфигураций виртуальных моделей** (основная настройка; см. ниже) |

**Конфигурация `virtual_models`:**

Каждая виртуальная модель — это шаблон со следующими полями:

| Поле | Тип | По умолчанию | Описание |
|------|------|-------------|----------|
| `name` | string | `"modelscope-auto"` | Имя виртуальной модели |
| `model_list` | list | `[]` | Список моделей ModelScope в порядке приоритета (минимум одна) |
| `fallback` | string | `""` | Опциональный резервный провайдер, используемый при недоступности всех моделей ModelScope |

**Примечания к полю `fallback`:**

Когда все модели ModelScope недоступны, запросы перенаправляются к настроенному OpenAI-совместимому провайдеру в AstrBot.

Это должен быть внешний провайдер (т.е. `api_base` не должен указывать на сам прокси), иначе он будет автоматически отключён.

Должен быть OpenAI-совместимым провайдером; иначе перенаправление невозможно.

**Пример конфигурации:**

```json
[
  {
    "name": "qwen-auto",
    "model_list": [
      "Qwen/Qwen3-Coder-480B",
      "Qwen/Qwen3.5-397B",
      "Qwen/Qwen3-393B"
    ],
    "fallback": ""
  },
  {
    "name": "qwen-fallback",
    "model_list": ["Qwen/Qwen3-235B-A22B"],
    "fallback": "openai/gpt-4o"
  }
]
```

Начиная с v0.3.1, плагин поставляется с тремя предустановленными виртуальными моделями:

- **modelscope-auto**: Модели с высокой производительностью
- **modelscope-auto-weak**: Модели с низкой производительностью
- **modelscope-auto-vision**: Модели для компьютерного зрения / мультимодальные

> Ранжирование возможностей по умолчанию может быть неточным. Не стесняйтесь корректировать или открыть issue при обнаружении несоответствий. Из-за нестабильности API ModelScope некоторые модели могут быть недоступны или работать некорректно — добавление или удаление моделей является нормальной практикой.

> ⚠️ Если `fallback` не настроен, запросы будут возвращать HTTP 503 при недоступности всех моделей ModelScope.

### 4. Добавление провайдера моделей в AstrBot

После запуска плагина настройте провайдера моделей в панели управления AstrBot:

1. Откройте панель управления → **Провайдеры моделей**
2. Добавьте провайдера типа **OpenAI API Compatible**
3. Заполните параметры:

| Параметр | Значение |
|-----------|---------|
| API URL | `http://127.0.0.1:3473/v1` (порт должен совпадать с `proxy_port`) |
| API Key | Если установлен `proxy_api_key`, используйте его значение; иначе любой заполнитель (не может быть пустым) |
| Имя модели | Нажмите "Получить список моделей" для автозаполнения (или введите вручную) |

### 5. Начало работы

После настройки вы можете использовать плагин в AstrBot как обычную OpenAI-модель. Плагин будет автоматически выбирать лучшую доступную модель по приоритету.

```bash
# Тест с помощью curl
curl http://127.0.0.1:3473/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen-auto",
    "messages": [{"role": "user", "content": "Привет!"}],
    "stream": true
  }'
```

**Использование с OpenAI SDK:**

```python
from openai import OpenAI

client = OpenAI(
    api_key="sk-placeholder",  # Используйте значение proxy_api_key, если настроено
    base_url="http://127.0.0.1:3473/v1"
)

response = client.chat.completions.create(
    model="qwen-auto",          # Используйте имя виртуальной модели
    messages=[{"role": "user", "content": "Привет!"}],
    stream=True
)
```

## Панель мониторинга

Плагин включает встроенную страницу мониторинга WebUI, доступную на странице деталей плагина в панели управления AstrBot (имя страницы: `monitor`). Панель отображает:

- **Глобальная квота пользователя**: текущий остаток / общее количество с индикатором прогресса, меняющим цвет в зависимости от остатка
- **Списки моделей ModelScope для каждой виртуальной модели**:
  - ID модели
  - Статус (доступна / отключена / перерыв)
  - Текущий остаток квоты (из последнего заголовка ответа)
- **Авто-обновление**: обновление каждые 30 секунд; также доступно ручное обновление

> **Примечание:** Данные квоты обновляются только при фактических запросах. Если сегодня запросы не отправлялись, общая квота и квоты моделей будут показаны как "Не получены".

## Логика маршрутизации

```
Запрос пользователя (с указанием имени виртуальной модели)
              ↓
      Сопоставление с конфигурацией виртуальной модели
              ↓
   ┌─────┴─────┐
   │ Квота польз. │  Если остаток ≤ global_quota_reserve, перейти к fallback или вернуть 503
   └─────┬─────┘
              ↓
   Выбрать первую доступную модель из model_list (по приоритету)
              ↓
       Перенаправление в ModelScope API
              ↓
    ┌────┴────┐
    │ Успех  │  →  Проверка заголовков: квота OK → вернуть результат
    └────┬────┘     квота исчерпана → отключить, переключиться
         ↓
    ┌────┴────┐
    │ Сбой   │  →  5xx/тайм-аут → отключить, переключиться
    └─────────┘     429 → подсчёт; 3 подряд → отключить
                    400 → перерыв 5 мин, переключиться
         ↓
   Все модели ModelScope недоступны?
         ↓
   ┌────┴────┐
   │ fallback │  →  Вызвать fallback и вернуть результат
   └────────────┘
         ↓
   Нет доступных сервисов → вернуть 503
```

- **Исчерпание квоты**: Все модели автоматически активируются в полночь.
- **Краткий перерыв**: HTTP 400 вызывает перерыв на 5 минут; HTTP 429 — перерыв на 2 минуты при первом срабатывании.
- **Глобальный резерв квоты**: При `modelscope-ratelimit-requests-remaining ≤ global_quota_reserve` срабатывает глобальное отключение — запросы к ModelScope не отправляются до сброса на следующий день.

## API эндпоинты

| Путь | Метод | Описание |
|------|-------|----------|
| `/v1/chat/completions` | POST | OpenAI-совместимое завершение чата (стриминг и не-стриминг) |
| `/v1/models` | GET | Возвращает список всех виртуальных моделей |
| `/v1/status` | GET | Внутренний статус плагина (отключён/перерыв для каждой модели) |
| `/v1/quota_status` | GET | Подробный статус квоты (для панели мониторинга) |

> **Примечание:** Если настроен `proxy_api_key`, все эндпоинты требуют Bearer-токен в заголовке `Authorization`.
